# 标书合规审查系统 — 前端页面设计文档

> 版本：2.0 | 日期：2026-05-08
> 前端技术栈：Vue 3 + Ant Design Vue + Pinia + Vite

---

## 1. 设计原则

- **入口 = 文件上传**，无需登录、无需创建项目
- 保留旧版 compliance_v2 的上传交互模式（Dragger + FileCard + 三步 Card 布局）
- 流水线监控、产物查看、报告渲染按 PRD 全新设计
- 后端自动创建 project + task，用户无感知
- 管理后台通过 Token 认证，查看所有提交记录

---

## 2. 路由设计

| 路由路径 | 页面 | 说明 |
|---------|------|------|
| `/reviewer/new` | UploadSubmit.vue | 上传与提交（用户入口） |
| `/reviewer/results/:id` | ResultPage.vue | 结果页（Token 保护，用户和管理员共用） |
| `/reviewer/admin` | AdminPage.vue | 管理后台（Token 认证，所有任务列表） |

**导航集成：** 在现有顶部导航栏 `src/layout/nav.vue` 中添加"审查"入口，指向 `/reviewer/new`。

**文件卡片（FileCard）样式：** 每个已上传文件显示为一行卡片，包含：
- 左侧图标（📄 PDF / 📝 DOCX）
- 文件名（加粗）
- 字数标签（参考字数标签样式表，见下方）
- 文件类型标签（绿色 `招标文件` / 蓝色 `投标文件`）
- 右侧删除按钮 🗑

**上传区域说明：** 只有一个 Dragger 拖拽区，系统自动识别文件是招标文件还是投标文件。招标文件限制 1 份，投标文件可多份。

**组件拆分：**

| 组件 | 说明 |
|------|------|
| FileUploadZone.vue | Dragger 拖拽上传区（区分 tender/bid） |
| FileCard.vue | 文件卡片（文件名/大小/字数/类型标签/删除按钮） |
| ContactForm.vue | 联系方式表单（姓名/公司/邮箱/手机/项目简称/项目说明） |
| SubmitCard.vue | 提交确认区 |

**API 映射：** 前端概念为"batch"，对应后端 `POST /api/v1/reviewer/projects`（自动创建 project）+ `POST /api/v1/reviewer/tasks`（自动创建 task）。前端用一个 `batchId` 关联两者，用户无感知。

**交互流程：**

1. 页面加载时调用后端 API 自动创建 project + task，获取 batchId
2. 用户拖拽/点击上传文件 → `POST /api/v1/reviewer/tasks/:id/upload` → 后端解析 PDF/DOCX → FileCard 实时更新状态
3. 招标文件限 1 份（docType=tender），重复上传返回 409；投标文件（docType=bid）可多份
4. 所有文件解析完成后，② ③ Card 解锁
5. 填写联系方式（姓名/公司/邮箱/手机/项目简称/项目说明）
6. 点击"启动合规审查" → `POST /api/v1/reviewer/tasks/:id/start`
7. 提交成功后跳转到 `/reviewer/results/:id?token=xxx`（token 为服务端返回的 progress_token）

**字数标签样式：**

| charCount | 样式 | 文案 |
|-----------|------|------|
| null | 红色 Tag | 解析失败 |
| < 50 且 PDF | 黄色 Tag | 扫描件 |
| < 50 | 黄色 Tag | 内容极少 |
| >= 5,000 | 绿色 Tag | N,NNN 字 |
| >= 500 | 绿色 Tag | N,NNN 字 |
| > 0 | 绿色 Tag | N 字 |

### 3.2 结果页 `/reviewer/results/:id`

**功能：** 流水线监控、审查产物查看、最终报告渲染

**访问控制：** URL 携带 `?token=xxx`。两种 Token 来源：
- **用户 Token（progress_token）**：提交审查时服务端返回，30 分钟有效，通过邮件发送给用户
- **管理员 Token（admin_token）**：管理后台登录时获取，可查看所有任务结果，存 sessionStorage

**布局：** 顶部信息条 + 4 个 Tab 切换

**阶段状态样式：**

| 状态 | 图标圆形 | 文字颜色 | 额外信息 |
|------|---------|---------|---------|
| 已完成 | 绿色背景 + 白色 ✓ | 绿色 | 显示耗时，Phase 4 显示质量评分 |

**WebSocket 事件处理：**

| 事件 | 处理 |
|------|------|
| phase_changed | 更新当前阶段，刷新 Steps |
| artifact_ready | 激活对应产物 Tab |
| agent_call_started | 显示加载状态 |
| agent_call_completed | 更新耗时显示 |
| completed | 标记完成，激活所有 Tab |
| failed | 显示错误信息 |

#### Tab 2：审查产物

5 个子 Tab，按流水线进度依次激活。子 Tab 为二级导航，位于主 Tab 下方：

```
  [审查基准 ✓]  [字段护照 ✓]  [BCA 结果 ✓]  [FCA 结果 ✓]  [审查报告 ✓]
  ═══════════
```

**子 Tab 激活状态：**
- 已激活且已就绪：绿色文字 + ✓ + 可点击
- 已激活但当前选中：绿色文字 + ✓ + 底部绿色下划线
- 未激活：灰色 + 禁用样式（cursor: not-allowed）

| 子 Tab | artifactType | 激活条件 | 渲染方式 |
|--------|-------------|---------|---------|
| 审查基准 | review_baseline | phase >= DPA_ROUND2 | Markdown 表格渲染 |
| 字段护照 | extracted_fields | phase >= BCA_FCA_RUNNING | Markdown 表格渲染 |
| BCA 结果 | bca_result | bca_result 存在 | Markdown 渲染 |
| FCA 结果 | fca_result | fca_result 存在 | Markdown 渲染 |
| 审查报告 | review_report | phase = COMPLETED | 专用报告渲染 |

**表格列布局（7 列 grid）：** 任务 ID(1.5fr) / 状态(0.8fr) / 联系人(1.2fr) / 文件数(0.6fr) / 当前阶段(1.2fr) / 提交时间(1.2fr) / 操作(0.6fr)

**联系人列：** 显示"姓名 · 邮箱"格式

**交互流程：**

1. 输入管理员 Token → 验证通过 → 进入列表页
2. 列表展示所有 task 记录，支持状态筛选（全部状态 / 已完成 / 审查中 / 失败）和时间排序
3. 运行中的 task 每 5 秒自动刷新
4. 点击"详情" → 跳转到 `/reviewer/results/:id?token=admin-xxx`（管理员 Token 可查看所有结果）
5. 管理员复用结果页，不需要独立详情页

**表格列定义：**

| 列名 | 字段 | 宽度比例 | 排序 | 说明 |
|------|------|---------|------|------|
| 任务 ID | id | 1.5fr | 否 | monospace 字体 |
| 状态 | status | 0.8fr | 是 | Tag 组件，颜色映射 |
| 联系人 | contactName + contactEmail | 1.2fr | 否 | "姓名 · 邮箱" 格式 |
| 文件数 | fileCount | 0.6fr | 否 | 招标+投标 |
| 当前阶段 | phase | 1.2fr | 否 | 阶段中文名，失败时红色 |
| 提交时间 | createdAt | 1.2fr | 是 | 默认倒序 |
| 操作 | — | 0.6fr | 否 | 蓝色"详情"链接 |

**状态颜色映射：**

| 状态 | Tag 颜色 | 文案 |
|------|---------|------|
| created | default(灰) | 待提交 |
| running | processing(蓝) | 审查中 |
| completed | green(绿) | 已完成 |
| failed | red(红) | 失败 |

## 4. 状态管理

### 4.1 useReviewerStore

```typescript
// stores/useReviewerStore/index.ts
interface ReviewerState {
  // 上传页
  batchId: string | null
  files: ReviewDocument[]
  uploading: boolean
}
```

| Action | 说明 |
|--------|------|
| createBatch() | 创建 batch（后端自动创建 project + task） |
| uploadFile(batchId, file, docType) | 上传文件 |
| deleteFile(batchId, fileId) | 删除文件 |
| submitBatch(batchId, contactInfo) | 提交联系方式并启动审查 |

### 4.2 useTaskResultStore

```typescript
// stores/useTaskResultStore/index.ts
interface TaskResultState {
  // 任务信息
  task: Task | null
  documents: ReviewDocument[]
  artifacts: Artifact[]

  // WebSocket
  wsConnected: boolean
  currentPhase: string

  // 活跃产物 Tab
  activeArtifactType: string | null

```

| Action | 说明 |
|--------|------|
| fetchTask(id, token) | 获取任务详情（含文件和产物列表） |
| fetchArtifact(taskId, type, token) | 获取指定产物内容 |

## 7. 交互流程

### 7.1 用户完整流程

```
1. 进入 /reviewer/new → 自动创建 batch
2. 上传招标文件 → FileCard 显示解析状态
3. 上传投标文件 → FileCard 显示解析状态
4. 填写联系方式（姓名/公司/邮箱/手机/项目简称/项目说明）
5. 点击"启动合规审查" → 提交
6. 自动跳转到 /reviewer/results/:id?token=xxx
7. 实时查看流水线进度（WebSocket）
8. 产物依次激活 → 随时查看已完成阶段的产物
9. 审查完成 → 查看最终报告
```

### 7.2 管理员流程

```
1. 进入 /reviewer/admin → 输入 Token
2. 查看所有提交记录列表
3. 点击"详情" → 跳转到 /reviewer/results/:id?token=admin-xxx
4. 复用结果页查看监控/产物/报告
```

### 7.3 邮件链接流程

```
1. 流水线完成后 → 系统发送邮件（含结果页链接）
2. 用户点击链接 → /reviewer/results/:id?token=xxx
3. Token 有效 → 展示结果页
4. Token 无效/过期 → 显示"链接无效或已过期"提示
```
