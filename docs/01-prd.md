# 标书合规审查系统 — 产品需求文档 (PRD)

> 版本：3.0 | 日期：2026-05-08
> 本文档只定义**系统做什么**（业务流程、数据模型、产物结构、交互流程）。
> 智能体的审查逻辑、判定规则、专家知识等**提示词内容**不在本文档范围内，由 prompt 配置管理。

---

## 1. 产品定位

### 1.1 一句话定义

标书合规审查系统 = **智能体编排流水线** + **审查产物管理**。

用户上传招标文件和投标文件，系统通过四智能体协作流水线自动完成合规审查，生成结构化审查报告。

### 1.2 目标用户

| 角色 | 场景 | 核心诉求 |
|------|------|---------|
| 审查负责人 | 上传文件，启动审查，查看报告 | 快速获得完整审查报告 |
| 标书编制人员 | 按报告中的否决项/缺陷项修改标书 | 清晰的整改建议和优先级 |
| 质量管理人员 | 监控审查进度，审查中间产物 | 实时了解流水线状态 |

### 1.3 产品范围

**包含：**
- 文件上传（PDF/DOCX），后端自动提取文本
- 四智能体协作审查流水线（ORA → DPA → BCA+FCA → ORA）
- 各阶段产物的格式校验与重试
- 报告质量评分（0-100 分，≥60 通过）
- 流水线实时状态推送（WebSocket）
- 各阶段审查产物查看

**不包含（后续迭代）：**
- PDF 报告导出
- 多轮审查历史对比
- 移动端适配
- 暂停/恢复审查流水线

## 2. 核心架构

### 2.1 智能体分工

```
                    ┌─────────────────────┐
                    │       ORA           │
                    │  编排调度 + 报告编译  │
                    └────────┬────────────┘
                             │
             ┌───────────────┼───────────────┐
             │               │               │
             ▼               ▼               ▼
     ┌──────────────┐ ┌──────────────┐ ┌──────────────┐
     │     DPA      │ │     BCA      │ │     FCA      │
     │  文档解析     │ │  业务审查     │ │  技术取证     │
     │  结构化提取   │ │  废标+胜算    │ │  风险+安检    │
     └──────────────┘ └──────────────┘ └──────────────┘
```

| 智能体 | 职责 | 输入 | 输出 |
|--------|------|------|------|
| **ORA** | 流程编排 + 报告编译 | BCA/FCA 结果 | 最终审查报告 |
| **DPA** | 非结构化 → 结构化转换 | 招标/投标文件原文 | 审查基准 + 字段护照 |
| **BCA** | 废标红线 + 中标胜算 | DPA 输出 + RAG 知识 | BCA 审查结果 |
| **FCA** | 隐蔽风险 + 电子文件安检 | DPA 输出 + RAG 知识 | FCA 审查结果 |

### 2.2 协作规则

1. **ORA 是唯一编排者** — DPA/BCA/FCA 不直接与用户交互
2. **BCA 与 FCA 并行** — 两者输入独立（都基于 DPA 输出），互不依赖
3. **结构化数据传递** — 智能体之间通过结构化 JSON 交换数据，非自然语言对话
4. **错误隔离** — 某维度审查异常不影响其他维度继续执行
5. **覆盖规则** — 若 BCA 发现否决项，FCA 仍正常执行，由 ORA 汇总时综合呈现

### 2.3 流水线阶段

```
文件上传
    │
    ▼
DPA Round 1 ─ 招标文件基准提取 ──→ 审查基准（4 张表）
    │
    ▼
DPA Round 2 ─ 投标文件字段提取 ──→ 字段护照（8 张表）
    │
    ▼
RAG 查询 ── 四维度知识检索 ──→ RAG 补充知识
    │
    ├──→ BCA（废标红线+中标胜算）──→ BCA 结果
    │
    └──→ FCA（隐蔽风险+电子安检）──→ FCA 结果
                │
                ▼
         ORA 报告编译 ──→ 最终审查报告
```

流水线通过 `phase`（当前阶段）+ `status`（运行状态）追踪进度。任何阶段失败时停留在当前阶段。

> 完整的状态机设计、数据流转、WebSocket 事件协议见 [`05-pipeline-design.md`](05-pipeline-design.md)。

## 3. 产物体系

每个流水线阶段产生一个独立产物，存入 `task_artifacts` 表。产物是流水线阶段之间的契约。

### 3.1 产物总览

| 产物类型 | 产出阶段 | 生产者 | 消费者 | 内容 |
|----------|---------|--------|--------|------|
| `review_baseline` | DPA_ROUND1 | DPA | BCA, FCA, ORA | 审查基准（4 张表） |
| `extracted_fields` | DPA_ROUND2 | DPA | BCA, FCA, ORA | 字段护照（8 张表） |
| `bca_result` | BCA_FCA_RUNNING | BCA | ORA | 废标红线 + 中标胜算 |
| `fca_result` | BCA_FCA_RUNNING | FCA | ORA | 隐蔽风险 + 电子文件安检 |
| `review_report` | REPORT_COMPILING | ORA | 用户 | 最终审查报告 |

### 3.2 DPA Round 1 — 审查基准

从招标文件提取 4 张结构化表：

**A. ★号条款提取表**

| 字段 | 说明 |
|------|------|
| ★条款编号 | 条款标识 |
| 条款原文摘要 | 原文关键要求 |
| 所在章节 | 招标文件中的位置 |
| 是否接受负偏离 | 是/否/未注明 |
| 所需支撑材料类型 | 检测报告/原厂证明/功能截图/… |

**B. 资格准入条件提取表**

| 字段 | 说明 |
|------|------|
| 条件类型 | 保密资质/社保/纳税/审计/… |
| 招标要求摘要 | 招标文件原文 |
| 所在章节 | 位置 |
| 是否标注废标 | 是/否 |

资格准入 9 个类型：军队采购供应商库、信用记录、营业执照、保密资质、涉密集成资质（如适用）、社保、纳税证明、审计报告、非外资背景。

**C. 评分标准提取表**

| 字段 | 说明 |
|------|------|
| 评分类别 | 商务/技术/价格 |
| 评分项名称 | 具体评分维度 |
| 满分 | 该项满分值 |
| 评分规则摘要 | 招标文件原文 |

**D. 格式与封装要求提取表**

| 字段 | 说明 |
|------|------|
| 要求类型 | 投标书格式/签章要求/文件命名/封装密封/保证金/授权委托书/递交截止时间 |
| 招标要求摘要 | 招标文件原文 |
| 所在章节 | 位置 |

### 3.3 DPA Round 2 — 字段护照

从投标文件提取 8 张结构化表：

| 序号 | 表格 | 关键字段 |
|------|------|---------|
| 1 | 公司基本信息 | 公司名称、信用代码、法人、注册资本、成立日期、营业期限、经营范围 |
| 2 | 资质证书信息 | 资质类型、证书编号、等级、有效期起止、持证单位 |
| 3 | 社保与纳税 | 参保单位、缴纳月份/期间、险种/税种 |
| 4 | 审计报告 | 审计年度、事务所、注册会计师、审计意见、双签双章 |
| 5 | 人员与授权 | 角色、姓名、身份证号、社保关系 |
| 6 | 业绩合同 | 合同名称、金额、签订日期、标的类别、双方 |
| 7 | 报价信息 | 分项名称、单价、数量、合价 |
| 8 | 项目名称一致性检查 | 文件名、出现的项目名称、是否与招标文件一致 |

### 3.4 BCA 审查结果

BCA 覆盖两个维度，6+3 个检查项：

**废标红线（6 项检查）**

| 检查项 | 说明 |
|--------|------|
| 1. 资格准入合规性 | 9 项资格条件逐项核验 |
| 2. 投标保证金与授权文件 | 保证金三要素 + 授权委托书五要素 |
| 3. 项目名称一致性 | 跨文件核对项目名称/编号 |
| 4. ★号条款对撞 | 响应自述 vs 支撑材料 vs 招标要求三方比对 |
| 5. 反串通与反雷同 | 文档元数据、图片 EXIF、文件哈希 |
| 6. 形式要件与附属文件 | 投标书格式、签章、日期、承诺函 |

**中标胜算（3 项评估）**

| 评估项 | 说明 |
|--------|------|
| 1. 商务响应竞争力 | 评分项 × 满分 × 预估得分 × 失分项 × 改进建议 |
| 2. 技术方案专业度 | 评分维度 × 满分 × 预估得分 × 评估依据 |
| 3. 经济合理性 | 算术校验、大小写一致性、异常低价预警、限价检查 |

每项检查输出统一格式：

```
检查项：{名称}
判定：PASS / FAIL / WARNING
招标要求：{原文摘要}
标书实际：{实际值，注明来源文件}
证据位置：{来源文件/页码}
是否否决项：是/否
详细说明：{判定依据}
整改建议：{如 FAIL}
```

### 3.5 FCA 审查结果

FCA 覆盖两个维度，2+5 个检查项：

**隐蔽风险探测（2 项）**

| 检查项 | 说明 |
|--------|------|
| 1. 暗标脱敏彻底性 | 7 项逐一检查（公司名/EXIF/遮盖层/矢量图/属性/栅格化/水印） |
| 2. 数据勾稽关系 | 4 方向双向核对（人员→报价、设备→清单、进度→函件、Excel→PDF） |

**电子文件安检（5 项）**

| 检查项 | 说明 |
|--------|------|
| 5.1 文件格式与平台兼容性 | PDF/A 标准、字体嵌入、颜色空间、禁止内容、文件大小 |
| 5.2 扫描件质量 | 分辨率(≥300dpi)、OCR 文本层、图像歪斜/黑边 |
| 5.3 电子签章合规 | CA 证书链、有效期、时间戳、签名算法、签章位置、多页独立性 |
| 5.4 文件命名与组织 | 命名规则、目录层级、多标段隔离 |
| 5.5 暗标反还原测试 | 删除 Annotation→OCR、开启 OCG 图层、栅格化→OCR |

每项检查输出格式同 BCA。

### 3.6 最终审查报告

报告结构（七章节 + 审查签署 + 附录 A-G）：

| 章节 | 内容 | 数据来源 |
|------|------|---------|
| 第一部分：项目概况与审查摘要 | 基本信息、审查结论看板、评审依据 | ORA 自动填写 |
| 第二部分：废标红线审查 | 资格准入(9项)、保证金/授权、★号条款对撞、反串通、形式要件 | BCA |
| 第三部分：中标胜算评估 | 商务得分预测、技术方案评分、经济合理性 | BCA |
| 第四部分：隐蔽风险探测 | 暗标脱敏检查、数据勾稽关系 | FCA |
| 第五部分：电子文件安检 | 文件格式、扫描件、签章、命名、反还原 | FCA |
| 第六部分：审查发现与整改建议 | 否决项清单、缺陷项、综合结论与投标建议 | ORA 汇总 |
| 第七部分：线下人工复核事项 | 6 项复核表 | ORA 预填 |
| 审查签署 | 审查人/复核人/批准人签字栏 | 留空 |
| 附录 A-G | 资格准入明细、元数据扫描、电子合规、签章验证、暗标还原、勾稽核验、证据索引 | ORA 自动生成 |

**审查结论看板字段：**

| 维度 | 审查状态 | 风险等级 |
|------|---------|---------|
| 废标红线 | 合格 / 存在风险 | 高/中/低 |
| 中标胜算 | 优 / 良 / 中 / 低 | 高/中/低 |
| 隐蔽风险 | 严谨 / 存在瑕疵 | 高/中/低 |
| 电子文件安检 | 合格 / 存在风险 | 高/中/低 |

**投标建议（三选一）：** 建议递交 / 有条件递交 / 不建议递交

## 4. 数据模型

### 4.1 实体关系

```
projects (1) ──→ (N) tasks
tasks (1) ──→ (N) review_documents
tasks (1) ──→ (N) task_artifacts
tasks (1) ──→ (N) llm_call_logs
```

### 4.2 枚举值

**ReviewVerdict — 审查判定：**

| 值 | 含义 |
|----|------|
| PASS | 通过 |
| FAIL | 不通过 |
| WARNING | 有风险需关注 |
| PENDING | 未判定 |

**RiskLevel — 风险等级：**

| 值 | 含义 |
|----|------|
| 高 | 含否决项 |
| 中 | 有失分风险 |
| 低 | 仅形式规范 |

### 4.3 审查报告数据结构

```
ReviewReport
├── project_code / project_name / review_date / bid_opening_date
├── waste_redline (DimensionSummary)      # 废标红线
│   ├── status: 合格 / 存在风险
│   ├── core_conclusion
│   ├── risk_level
│   ├── rejection_items[]
│   ├── defect_items[]
│   └── results: ComplianceResult[]
├── scoring_evaluation (DimensionSummary)  # 中标胜算
│   ├── status: 优/良/中/低
│   └── ...
├── hidden_risk (DimensionSummary)         # 隐蔽风险
│   ├── status: 严谨 / 存在瑕疵
│   └── ...
├── file_inspection (DimensionSummary)     # 电子文件安检
│   ├── status: 合格 / 存在风险
│   └── ...
├── overall_conclusion
├── bid_recommendation                     # 投标建议（三选一）
├── rejection_list[]
├── defect_list[]
└── manual_review_items[]
```

### 4.4 单项检查结果

```
ComplianceResult
├── check_id                  # 检查项 ID
├── dimension                 # 维度
├── check_item                # 检查项名称
├── verdict: ReviewVerdict    # PASS/FAIL/WARNING/PENDING
├── requirement               # 招标要求
├── actual                    # 标书实际值
├── evidence_location         # 证据位置
├── is_rejection              # 是否否决项
├── detail                    # 详细说明
└── fix_suggestion            # 整改建议
```

## 5. 文件处理

### 5.1 文件上传

**允许格式：** `.pdf`, `.docx`, `.doc`
**大小限制：** 单文件 ≤ 100MB

| 文件类型 | 必需性 | 说明 |
|---------|--------|------|
| 招标文件 | 必需 | 含投标人须知、★号条款、评分标准等 |
| 投标文件（技术标） | 必需 | 技术方案、总体架构等 |
| 投标文件（商务标） | 必需 | 报价汇总、分项报价、业绩证明等 |
| 投标文件（资质证明） | 必需 | 营业执照、保密资质、社保纳税等 |
| 招标附件 | 可选 | 格式模板、技术规格补充等 |

**约束：**
- 每个任务仅 1 份招标文件（docType=tender），重复上传返回 409
- 投标文件（docType=bid）可上传多份
- 启动审查前必须已上传招标文件 + 至少 1 份投标文件

### 5.2 文件存储

文件本体存磁盘，数据库只存元数据（文件名、大小、路径、docType）。

**存储路径：** `data/uploads/{taskId}/{fileName}`

**文件下载：** 提供 `GET /tasks/:id/documents/:docId/download` 接口，返回原始文件。

### 5.3 文本提取

文本提取在用户点击"开始审查"（`POST /tasks/:id/start`）时触发，不在上传时执行。流水线引擎启动后首先提取所有文件的文本（pdf-parse / mammoth），存入 `review_documents.textContent`。

**charCount 语义：**

| charCount | 含义 |
|-----------|------|
| null | 文本提取失败 |
| < 50 且为 PDF | 可能是扫描件 |
| ≥ 5,000 | 内容完整 |
| ≥ 500 | 内容基本完整 |

### 5.4 文本截断策略

各阶段 Prompt 构建时的截断上限：

| 阶段 | 输入 | 截断上限 |
|------|------|---------|
| DPA R1 | 招标文件全文 | 45,000 字符 |
| DPA R2 | 优先投标文件 | 15,000 字符/文件 |
| DPA R2 | 其他投标文件 | 4,000 字符/文件 |
| DPA R2 | 审查基准 | 10,000 字符 |
| BCA | 审查基准 | 12,000 字符 |
| BCA | 提取字段 | 12,000 字符 |
| FCA | 投标文件合并文本 | 15,000 字符 |
| FCA | 提取字段 | 8,000 字符 |
| ORA | 招标文件摘要 | 4,000 字符 |
| ORA | 审查基准 | 6,000 字符 |
| ORA | BCA 结果 | 12,000 字符 |
| ORA | FCA 结果 | 12,000 字符 |

## 6. 质量保障

### 6.1 两层校验

| 层级 | 校验对象 | 校验方式 | 失败处理 |
|------|---------|---------|---------|
| 第一层：格式校验 | DPA/BCA/FCA 输出 | 代码级正则匹配 | 追加修正要求，重试最多 3 次 |
| 第二层：质量评分 | ORA 最终报告 | 结构+表格+AI痕迹+标题编号综合评分 | 追加问题清单，重试最多 3 次 |

### 6.2 第一层格式校验规则

| Agent | 校验规则 |
|-------|---------|
| DPA R1 | 必须包含 4 张表（★号条款/资格准入/评分标准/格式封装） |
| DPA R2 | 6 类字段表中至少找到 3 类 |
| BCA | 必须含 PASS/FAIL 判定，检查项 ≥ 2，含否决项/缺陷项汇总 |
| FCA | 必须含 PASS/FAIL 判定，检查项 ≥ 2，含文件命名检查 |

### 6.3 第二层报告质量评分

满分 100 分，≥60 且缺少章节 ≤ 2 视为通过：

| 维度 | 扣分 |
|------|------|
| 每缺少 1 个关键章节 | -10 |
| 每缺少 1 个数据表 | -8 |
| 每检出 1 处 AI 痕迹 | -15 |
| 缺少投标建议 | -15 |
| 报告 <500 字 | -20 |

### 6.4 重试机制

```
for attempt in range(3):
    result = call_llm(prompt)
    if result 为空: continue
    issues = validate_format(result)
    if issues 为空: 保存结果 → return
    if attempt < 2:
        prompt += 格式修正要求(issues)
# 最后一次结果即使格式不完美也保留（优雅降级）
```

## 7. RAG 知识库

### 7.1 定位

RAG 是四维度知识补充引擎。在 DPA 完成解析后、BCA/FCA 执行前，通过向量检索获取补充检验知识和历史案例。

### 7.2 查询时机

| 时机 | 说明 |
|------|------|
| 必查 | DPA R2 完成后、BCA/FCA 执行前 |
| 按需 | 遇到未覆盖的特殊资质类型/文件格式 |

## 11. 验收标准

### 11.1 功能验收

1. 用户上传招标文件（1 份）和投标文件（多份），系统自动识别文件类型并提取文本
2. 启动审查后，流水线按 DPA R1 → DPA R2 → BCA+FCA(并行) → ORA 顺序执行
3. 执行过程中前端通过 WebSocket 实时显示阶段和状态
4. 每阶段完成后，用户可立即查看该阶段产物
5. 最终报告包含七章节 + 审查签署 + 附录 A-G
6. 报告包含明确的投标建议（三选一）

### 11.2 质量验收

1. 报告必须包含 7 个章节 + 附录 A-G
2. 报告不得包含 AI 痕迹
3. 所有无决项必须有完整证据链
4. 报告质量评分 ≥ 60 且缺少章节 ≤ 2

### 11.3 业务逻辑验收

1. DPA 不得将"未提取到"等同于"文件缺失"
2. BCA/FCA 的 FAIL 判定必须有完整证据链，否则降级为 WARNING
3. BCA+FCA 结果矛盾时两处判定都保留
4. ORA 不得升级或降级 BCA/FCA 的原始判定

## 12. 术语表

| 术语 | 含义 |
|------|------|
| DPA | 文档解析智能体 — 非结构化→结构化转换 |
| BCA | 业务审查智能体 — 废标判定+得分预测 |
| FCA | 技术取证智能体 — 暗标还原+电子文件安检 |
| ORA | 审查编排智能体 — 流程总控+报告编译 |
| ★条款 | 招标文件中标注★的实质性要求 |
| 废标红线 | 会导致投标被否决的硬性违规项 |
| 字段护照 | 从投标文件中提取的结构化数据（8 张表） |
| 勾稽关系 | 不同文件间数据的一致性关系 |
| 否决项 | 不修复直接导致废标的问题 |
| 缺陷项 | 不导致废标但有失分风险的问题 |
| 证据链 | 判定的完整依据（招标要求→标书实际→差异→来源） |
