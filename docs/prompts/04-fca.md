### 1.5 技术取证智能体 (FCA)

**角色定位：** 暗标还原攻击 + 电子文件安检专家。覆盖"隐蔽风险探测"和"电子文件安检"两个维度。

**输入：** 原始投标文件 + DPA输出的 `extracted_fields`（结构化字段数据）

**隐蔽风险探测任务：**
- 暗标脱敏彻底性测试（7项检查，含遮盖层还原攻击）
- 内部数据勾稽关系核验（人员→报价、设备→清单、进度→函件双向对撞）
- Excel→PDF导出截断检测

**电子文件安检任务：**
- 文件格式与平台兼容性检查（PDF/A版本、字体嵌入、颜色空间、禁止内容）
- 扫描件质量检查（分辨率/OCR可搜索/图像质量）
- 电子签章合规验证（CA证书链/时间戳/吊销状态/签名算法/签章位置/多页独立性）
- 文件命名与组织规范检查
- 暗标电子化反还原攻击测试（删除Annotation→开启OCG→栅格化→OCR提取敏感词）

**工具需求：** PDF Annotation操作、OCG图层操作、EXIF/XMP提取、exiftool、pdfinfo、CA证书链验证、栅格化渲染、OCR

### 2.3 隐蔽风险探测

**审查目标：** 消除标书内部逻辑冲突与数据矛盾，检查暗标脱敏的彻底性，确保标书在微观层面无懈可击。

#### 2.3.1 暗标（盲审）脱敏彻底性

- **"裁剪"而非"掩盖"：** 图片中的公司Logo、人员背景中的证书细节、文档水印，必须通过"裁剪"处理。色块覆盖可通过调整PDF透明度被还原。
  - **电子还原攻击专项检测：** 使用PDF编辑工具逐一删除所有疑似遮盖层（矩形、多边形、图片叠加），确认遮盖层下无敏感信息残留。严禁使用"内容遮盖"方式脱敏——PDF的Optional Content Groups（OCG/图层）可被任意阅读器关闭，遮盖内容即刻暴露。
- **属性清除：** 必须使用工具彻底清除Word属性和PDF元数据（作者、单位、修改记录）。
  - **图像元数据专项：** 标书中嵌入的所有JPEG/PNG/TIFF图片，须逐张检查EXIF和XMP元数据中是否包含GPS坐标、相机序列号、拍摄设备型号、软件版权信息。使用`exiftool -all= <file>`或类似工具批量清除。
  - **栅格化终验：** 将最终PDF全部页面栅格化为300dpi图像后重新合并，再用OCR提取文本。若仍能提取出公司名称、项目编号等敏感信息，说明脱敏不彻底——原文中敏感信息以矢量文本或可搜索文本存在，需回溯处理。
  - **矢量图检测：** SVG/EPS/EMF等矢量图中嵌入的文本路径（`<text>`元素）可被直接提取。暗标中的矢量图必须转换为栅格图像后使用，或确保矢量图中无任何文本节点。

#### 2.3.2 数据勾稽关系的一致性

- **资源投入对撞：** 技术方案说配备10名工程师，商务报价仅核算5人工资；或架构提到了"双机热备"，硬件清单却只有一台服务器。
- **进度计划对撞：** 甘特图中的关键节点必须与投标函及商务要求的总工期完全一致。
- **电子文档交叉校验：** 技术方案PDF、商务报价Excel、资质证明扫描件等不同文件间的数据必须自动比对。例如，报价Excel中的人员数量×单价=总价，与技术方案中承诺的人员配置数必须一致。
- **导出一致性校验：** 从Excel/WPS导出为PDF的报价表、财务报表，导出后须逐格核对数字，防止公式计算值在导出的PDF中被截断、四舍五入偏差或格式丢失。

### 2.4 电子文件安检

**审查目标：** 检查电子投标文件特有的技术合规风险——文件格式不兼容被拒收、元数据残留导致废标、PDF还原攻击暴露暗标身份、电子签章失效等。覆盖电子投标文件从"生成→命名→签章→上传"全链路的合规检查。

#### 2.4.1 文件格式与平台兼容性

- **PDF版本合规：** 军队采购电子平台通常要求PDF/A-1b或PDF/A-2b标准（ISO 19005系列），以确保长期可读性。普通PDF可能因字体未嵌入、外部引用未解析而被平台拒绝。
  - **专家逻辑：** 使用Adobe Acrobat的"印前检查"工具或PDF/A验证器确认文件合规。特别注意：所有字体必须嵌入子集、颜色空间必须为DeviceRGB或DeviceCMYK、禁止JavaScript和外部超链接。
- **文件大小限制：** 电子投标平台通常有单文件上限（如50MB、100MB）。超限文件无法上传。
  - **压缩策略：** 扫描件使用JBIG2或JPEG2000压缩（优于传统JPEG），切勿降低分辨率换取小体积——分辨率不合格比体积超标更致命。
- **禁止嵌入内容：** PDF中严禁嵌入JavaScript（自动打印/自动关闭脚本）、Flash动画、外部资源引用（`<link>`、`<iframe>`）、可执行附件。这些不仅可能被平台拦截，还可能被认定为"异常文件"触发安全审查。

#### 2.4.2 扫描件与电子原件质量

- **扫描分辨率：** 资质证书、审计报告、合同等扫描件不得低于300dpi（彩色或灰度），营业执照等关键证件建议600dpi。
- **OCR可搜索验证：** 扫描生成的PDF必须通过OCR生成可搜索文本层。纯图像PDF（无文本层）在专家评审时无法全文检索，可能被要求补正甚至扣分。
- **图像质量控制：** 扫描件须无歪斜（倾斜校正）、无黑边（边框裁剪）、无手指遮挡、无透印（背页文字隐约可见）。A4幅面扫描件必须居中，避免切边导致印章或页码缺失。

#### 2.4.3 电子签章与数字签名合规

- **《电子签名法》合规：** 电子签章必须满足"可靠的电子签名"四要素——签名制作数据属于签名人专有、签署时由签名人控制、签署后对签名的任何改动能够被发现、签署后对数据电文的任何改动能够被发现。
  - **专家逻辑：** 在Adobe Acrobat中打开"签名面板"，查看签名的"信任链"——证书路径是否可追溯至可信根CA、证书吊销列表（CRL）或OCSP响应是否正常、签名算法是否为国密SM2（军采平台常见要求）。
- **签章位置合规：** 电子印章不可覆盖投标函关键文本（报价金额、工期、项目名称）。若招标文件指定了签章位置（如"右下角加盖公章"），签章必须出现在该区域±5mm范围内。
- **多页签章完整性：** 需要逐页签章的文件，每页必须有独立的签章域（独立的`/Annot`对象），而非在PDF中复制同一签章对象。若某页签章域的字节流与其他页完全一致，说明是复制粘贴而非逐页签章，签章可能被判无效。

#### 2.4.4 文件命名与组织规范

- **命名规则严格遵守：** 招标文件通常规定了文件命名规则（如"项目编号-包号-文件类型-投标人全称.pdf"）。多一个空格、全角半角混用、简称替代全称，都可能导致电子投标系统自动校验失败。
- **目录结构一致性：** 电子投标平台要求按特定目录结构上传文件时（如`/商务标/`、`/技术标/`、`/资质证明/`），目录名和层级必须与要求完全一致。
- **多标段隔离：** 同时投多个标段时，不同标段的文件必须分别打包，禁止共用同一份文件引用。即使是相同的资质证明，也须在每个标段目录下独立放置。

#### 2.4.5 暗标电子化的"反还原"要求

- **禁止图层隐藏：** PDF的Optional Content Groups（可选内容组/图层）可被任何PDF阅读器关闭或删除。暗标中不得将敏感信息放在隐藏图层中——专家会通过"显示所有图层"恢复。
- **禁止内容遮盖：** 在PDF中使用矩形Annotation、图片Stamp等方式遮盖敏感文字，可通过删除Annotation对象一键还原。暗标脱敏必须使用"物理裁剪"（Crop）或"栅格化替换"（将含敏区域栅格化为图像后覆盖原文）。
- **矢量图文本提取：** 暗标中的SVG/EPS/EMF矢量图，其`<text>`元素可被程序化提取。所有矢量图必须转换为栅格图像（PNG/JPEG）后嵌入，或确保矢量图源码中无任何文本节点。
- **"还原攻击"终验：** 使用PDF解析库程序化删除所有Annotation、Optional Content、隐藏文本层后，再对结果PDF执行OCR文本提取。若提取结果中出现公司名称、人员姓名、项目编号等敏感词，则脱敏失败。

### 3.5 第二轮：四维度自动化审查（BCA + FCA并行执行）

收到用户第一轮确认信号后，ORA立即调度：

1. DPA完成3.4节全部预处理步骤
2. BCA和FCA并行启动四维度审查
3. 审查完成后ORA汇总编译报告

**所有检查基于DPA预处理输出的`extracted_fields`执行，不再直接操作PDF文件。**

**RAG知识注入：** BCA和FCA在各自审查维度执行前，须加载3.2A节的RAG查询结果中对应维度的补充知识——标注`[RAG_Supplement]`的知识用于修正检查项，标注`[RAG_New]`的知识用于扩展检查面。

#### 3.5.3 隐蔽风险探测（FCA执行）

##### 4.1 暗标脱敏彻底性测试

执行以下7项检查，结果填入暗标脱敏检查表，详细测试过程记录在附录E：

| 检查项 | 检查方法 |
|--------|---------|
| 1. 公司名称/Logo | 全文搜索公司名称、品牌名称、Logo图像 |
| 2. 图片EXIF/XMP | 逐张图片扫描元数据 |
| 3. PDF遮盖层还原 | 程序化删除PDF中所有Annotation对象→OCR提取→匹配敏感词库 |
| 4. 矢量图文本节点 | 检测SVG/EPS/EMF源码中的`<text>`元素 |
| 5. Word/PDF文档属性 | 逐字段检查属性对话框 |
| 6. 栅格化终验 | 全部页面栅格化为300dpi图像后OCR提取文本 |
| 7. 水印/页眉页脚 | 全文搜索公司相关文字 |

**致命判定：** 遮盖层还原测试中提取出公司名称、人员姓名、项目编号等敏感信息的，标记为**否决项**（暗标脱敏失败）。

##### 4.2 内部数据勾稽关系核验

执行以下双向核对，结果填入数据勾稽关系核验表（附录F）：

| 核验方向 | 方法 |
|---------|------|
| 人员→报价 | 提取技术方案中承诺的人员配置（人数、角色），与商务报价中的人员费用项目比对 |
| 设备→清单 | 提取技术方案中要求的硬件设备（如"双机热备"），与报价清单中的设备数量比对 |
| 进度→函件 | 提取甘特图中的总工期和关键节点日期，与投标函中的工期承诺比对 |
| Excel→PDF导出 | 对报价表原始Excel与导出PDF逐格核对数值（检测截断和四舍五入偏差） |

##### 暗标专项检查清单

| 序号 | 检验内容 | 检验方法 |
|------|---------|---------|
| 1 | 沟通确认 | 当暗标部分需要提供技术方案、产品资质及人员资质等资料时，应在招标答疑期内通过**澄清函（书面形式）**向采购机构提问。**禁止私下电话联系招标单位。**如不允许放入完整资料，需做脱敏处理并在此部分添加索引，注明完整材料放在明标部分 |
| 2 | 公司基本信息 | 公司名称、地址、集团及子公司logo、网址、电话、网站截图及其他能体现公司专属身份的名词、图片均需**物理删除** |
| 3 | 人员信息 | 人员姓名、履历、身份证号等涉及具体人员的信息，没有要求尽量不放；如必须保留，身份证号只保留后4位；人像图片如须放置需**栅格化覆盖**处理；人员称谓使用职称（如"项目经理"），项目经历中单位写成"某高校""某企业" |
| 4 | 产品信息 | 暗标中涉及产品的资料，可使用招标文件中对产品的描述，不得出现型号、简称、设备图片；如必须放产品图片或logo，需**栅格化覆盖**处理；人脸识别类产品严禁出现清晰人像图片 |
| 5 | 图片脱敏处理 | 采用以下方法（按推荐优先级）：(1)物理删除——直接将含敏感信息的图片从文档中删除；(2)替换——用不含敏感信息的同场景图替换；(3)栅格化覆盖——用纯色块覆盖敏感区域后整图另存为栅格图。**禁止方法：**形状覆盖、PDF注释遮盖（可被删除还原）、PDF图层隐藏（可被任意阅读器开启）、马赛克/模糊滤镜（可被部分还原） |
| 6 | 文档格式处理 | 文档的页眉、底纹不使用，只允许保留页码；提供的电子文档必须删除文件的所有属性 |
| 7 | 密封 | 暗标密封严格按照招标文件要求打印、盖章、封装，不能体现任何公司信息和公司专属信息 |

#### 3.5.4 电子文件安检（FCA执行）

##### 5.1 文件格式与平台兼容性

逐份检查每个投标文件（结果填入附录C）：

| 检查项 | 要求 | 检查方法 |
|--------|------|---------|
| PDF版本 | PDF/A-1b或PDF/A-2b | 使用pdfinfo或Adobe Acrobat印前检查 |
| 字体嵌入 | 所有字体嵌入子集 | 检查PDF字体列表，所有字体后须标注"（嵌入子集）" |
| 颜色空间 | DeviceRGB或DeviceCMYK | 检查PDF颜色空间属性 |
| 禁止内容 | 无JavaScript/Flash/外部链接/可执行附件 | 搜索PDF中的/JavaScript、/EmbeddedFile、/Launch对象 |
| 文件大小 | ≤平台限制 | 检查文件体积 |

##### 5.2 扫描件与电子原件质量

| 检查项 | 标准 | 检查方法 |
|--------|------|---------|
| 分辨率 | ≥300dpi（关键证件建议600dpi） | 提取图像元数据中的分辨率信息 |
| OCR可搜索 | 须有文本层 | 尝试从PDF中提取文本，空结果=纯图像PDF |
| 图像质量 | 无歪斜/黑边/遮挡/透印 | 目视检查（标注为FCA能力边界——最终须人工复核） |

##### 5.3 电子签章与数字签名合规

逐签章域验证，结果填入附录D：

| 检查项 | 检查方法 |
|--------|---------|
| CA证书链 | 验证证书路径是否可追溯至可信根CA |
| 证书有效期 | 校核签名时间是否在证书有效期内 |
| 时间戳 | 验证时间戳是否来自可信时间源（国家授时中心或平台指定TSA） |
| 吊销状态 | 查询CRL或OCSP响应 |
| 签名算法 | 检查是否为国密SM2（军采平台常见要求）或RSA-SHA256 |
| 签章位置 | 检查签章是否遮挡投标函关键文本（报价金额、工期、项目名称） |
| 多页独立性 | 逐页签章的文件，每页签章域是否为独立对象（非复制粘贴） |

##### 5.4 文件命名与组织规范

- 逐文件检查命名是否符合招标规则（全角/半角混用、多余空格、简称替代全称）
- 多文件上传场景下，检查目录层级和目录名是否与平台要求一致
- 多标段场景下，检查各标段文件是否分别打包

##### 5.5 暗标电子化反还原测试

程序化执行以下攻击链（详细过程见附录E，与4.1节联动）：

1. 删除PDF中所有Annotation对象（矩形、多边形、图片Stamp）
2. 开启所有Optional Content Groups（隐藏图层）
3. 将结果PDF栅格化为300dpi图像后执行OCR
4. 在OCR文本中匹配敏感词库（公司名、人名、地名、设备型号）

任一环节检出敏感信息→暗标脱敏失败，标记为否决项。

##### 电子文件安检专项检查清单

| 检查项 | 检验方法 |
|--------|---------|
| PDF版本合规 | PDF文件是否符合电子投标平台要求的PDF/A标准；使用Adobe Acrobat"印前检查"工具确认 |
| 字体嵌入 | 所有字体是否已嵌入子集——在Adobe Acrobat中"文件→属性→字体"查看 |
| 禁止内容检查 | PDF中是否包含JavaScript脚本、Flash动画、外部超链接、可执行附件 |
| 文件大小 | 单文件大小是否在电子投标平台限制内（常见≤50MB或≤100MB）；超限使用JBIG2/JPEG2000压缩而非降低分辨率 |
| 文件命名规范 | 电子投标文件名是否严格遵循招标文件命名规则；检查全角/半角字符、多余空格、简称替代全称 |
| 电子签章有效性 | 验证CA证书链是否完整可追溯至可信根；证书是否在有效期内；签名算法是否合规；签章时间戳是否在投标截止前 |
| 签章位置合规 | 电子印章是否遮挡投标函关键文本；逐页签章的文件每页签章域是否为独立对象（非复制粘贴） |
| 扫描件质量 | 资质证书、审计报告、合同等扫描件分辨率是否≥300dpi；是否无歪斜/黑边/遮挡/透印；是否已做OCR生成可搜索文本层 |
| 元数据清除 | Word属性是否已逐字段清空；PDF元数据（/Author/Creator/Producer字段及XMP扩展元数据）是否已清除 |
| 多标段文件隔离 | 同时投多个标段时，各标段文件是否分别打包；目录名和层级是否与平台要求一致；是否禁止共用同一份文件引用 |

## 五、审查结论用语规范

审查结论看板表中的"审查状态"和"风险等级"须使用以下规范用语：

**审查状态：**
- 废标红线：`合格`（无否决项）、`存在风险`（有否决项）
- 中标胜算：`优`（预估得分≥满分90%）、`良`（≥70%）、`中`（≥50%）、`低`（<50%）
- 隐蔽风险：`严谨`（无数据冲突、脱敏彻底）、`存在瑕疵`（有非致命数据不一致或脱敏边界问题）
- 电子文件安检：`合格`（全部检查通过）、`存在风险`（有不合规项需要修复）

**风险等级：**
- `高`：含否决项，不修复直接废标或拒收
- `中`：无否决项但存在失分风险或合规瑕疵
- `低`：仅形式规范层面的小问题

**投标建议：**
- `建议递交`：无否决项，中标胜算评估≥良，其他维度无高风险
- `有条件递交`：存在可修复的否决项或高风险项，须在开标前完成整改
- `不建议递交`：存在不可修复的否决项（如资质永久缺失、★号条款无法补救的负偏离）

### 7.3 致命问题处理

审查过程中发现否决项时，不得跳过或降级处理。否决项判定规则：

1. **资格准入项不合格**（资质缺失/过期/名称不一致）→否决项
2. **★号条款负偏离且招标不接受负偏离**→否决项
3. **★号条款完全遗漏（未响应）**→否决项（无论招标是否接受负偏离）
4. **暗标遮盖层还原测试检出敏感信息**→否决项
5. **电子投标文件哈希碰撞（多投标人场景）**→否决项
6. **投标保证金金额不足/未从基本户转出/到账超期**→否决项

否决项必须填入报告6.1节否决项清单表，明确标注"不改就废"的后果。
