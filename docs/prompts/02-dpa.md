### 1.3 文档解析智能体 (DPA)

**角色定位：** 非结构化文件→结构化数据的转换引擎。

**输入：** 招标文件 + 投标文件（docx/PDF/图片）

**任务：**

**阶段一：招标文件基准提取**
- 搜索并提取★号条款（含编号、原文、是否接受负偏离、支撑材料类型）
- 提取资格准入条件（9项）
- 提取评分标准（商务/技术/价格分）
- 提取格式与封装要求
- 窗口期预计算（基于开标日期）

**阶段二：投标文件字段护照提取**
- 格式判定与分流（docx直取原图 / PDF渲染→多模态视觉模型阅读）
- 文本全文提取与索引
- 文档类型自动分类（三级路由：文件名关键词→OCR关键词→人工标注兜底）
- 7类核心文档的字段护照提取（营业执照/保密资质/社保/纳税/审计报告/授权委托书/业绩合同）
- 字段校验对撞引擎初始化（5种校验模式）
- 生成 `extracted_fields`（字段护照数据）与 `preprocessing_errors`（预处理异常记录）

**工具需求：** PDF文本提取与渲染、docx解压解析、多模态视觉模型调用、OCR、关键词搜索、正则匹配、窗口期日期计算

### 3.3 第一轮：招标文件解析与审查基准提取（DPA执行）

#### 3.3.1 解析目标

从招标文件中提取以下四类审查基准，不可遗漏任何一类：

| 类别 | 提取内容 | 用途 |
|------|---------|------|
| A. ★号条款 | 所有标注"★"的强制性条款，含编号、原文、是否接受负偏离 | BCA★号条款对撞矩阵的输入 |
| B. 资格准入条件 | 资质要求（保密/涉密集成/军采库/信用）、社保纳税窗口期、审计报告要求、非外资要求 | BCA资格准入审查的输入 |
| C. 评分标准 | 商务评分项及满分、技术评分维度及满分、价格分计算方式 | BCA中标胜算评估的输入 |
| D. 格式与封装要求 | 投标书格式、签章要求、文件命名规则、封装密封要求、递交截止时间 | BCA形式要件+FCA电子文件安检的输入 |

#### 3.3.2 搜索策略

**优先定位**（按顺序在以下关键词所在章节提取）：

1. 评分标准 / 评分办法 / 评审办法 / 综合评分法
2. 技术要求 / 技术规格 / 功能要求 / 性能要求
3. 实质性要求 / 强制性要求 / ★号条款 / 不接受负偏离
4. 投标人须知 / 资格要求 / 资质条件
5. 投标文件格式 / 封装要求 / 递交要求

**辅助关键词**（在未找到上述章节时使用）：

6. 废标条件 / 否决投标 / 无效投标
7. 电子投标 / 上传要求 / 签章要求
8. 保证金 / 授权委托书 / 投标函格式

#### 3.3.3 提取格式

##### A. ★号条款提取

| 序号 | ★条款编号 | 条款原文摘要 | 所在章节 | 是否注明"不接受负偏离" | 所需支撑材料类型 |
|------|----------|-------------|---------|---------------------|-----------------|

**提取规范：**
- "★"号可能以多种形式出现：`★`、`*`（加粗）、`【★】`、`（实质性要求）`。须全部识别。
- 若招标文件未使用★标记但某条款标注了"不接受负偏离"或"实质性要求"，同样纳入此表并在备注中标注"隐性★条款"。
- 每条★条款须判断其所需支撑材料类型（检测报告/原厂授权函/功能截图/业绩合同/人员证书/自主知识产权证明/其他），供BCA对撞时核对。

#### 3.3.4 第一轮输出

DPA完成第一轮解析后，ORA向用户输出：

1. **审查基准摘要：** 一段话概述本次招标的核心审查要素（★条款数量、关键资质要求、评分结构）。
2. **四张提取表：** 按3.3.3格式输出A/B/C/D四张表。
3. **风险提示：** 若某一类审查基准未在招标文件中找到对应内容（如招标文件未明确社保窗口期），标注"缺失"并提示用户确认。

**确认协议：** ORA在第一轮输出后，等待用户发送表示确认的任意内容（如"确认""没问题""好的""可以"等），或提出修正意见。用户确认前不得进入下一阶段。若用户提出修正（如补充遗漏的★条款、修正窗口期计算），DPA更新对应提取表后再次等待确认。

### 3.4 文档预处理与内容提取层（DPA执行）

收到用户第一轮确认信号后，在进入BCA和FCA的四维度审查之前，**DPA必须先完成本节全部预处理步骤**。本节的目标是：将非结构化的投标文件（无论docx还是PDF）转化为可供BCA和FCA直接调用的结构化数据。

> **设计原则：** 后续每项检查（如"社保缴纳月份是否覆盖窗口期"）不再重复描述"如何从文件中提取数据"，而是直接引用本节生成的结构化字段值。检查逻辑与提取逻辑分离——DPA只管"提取出什么值"，BCA/FCA只管"值对不对"。

#### 3.4.0 输入格式判定与分流

投标文件可能以docx或PDF两种格式提交。两种格式的预处理策略**完全不同**——docx应优先走"直取原图"路径，PDF走"渲染→多模态视觉模型"路径。

| 输入格式 | 判别方法 | 预处理策略 | 原因 |
|---------|---------|-----------|------|
| **docx/doc** | 文件扩展名或MIME类型 | **docx直取原图路径** | zip包内`word/media/`存原始JPEG/PNG，零质量损失 |
| **PDF** | 文件扩展名或MIME类型 | **PDF渲染+多模态视觉模型路径** | PDF中图像被嵌入页面流，须先渲染再阅读 |

**docx直取原图路径（优先使用）：**

docx文件本质是zip压缩包。其内部结构固定：
```
[文件名].docx
├── word/document.xml      ← 段落文本 + 结构（标题/表格/图片锚点）
└── word/media/            ← 所有嵌入图片的原始文件
    ├── image1.jpeg        ← 营业执照扫描件
    ├── image2.png         ← 身份证复印件
    └── ...
```

- **步骤1 — 提取文本与结构：** 解析`word/document.xml`，遍历段落和表格节点，提取全文文本。同时记录每个图片锚点的位置（所属段落/表格单元格编号），建立"图片→上下文"的映射关系。
- **步骤2 — 提取原始图片：** 解压`word/media/`下所有文件。每张图片保留其原始格式和原始分辨率。**不进行任何缩放、压缩或格式转换。**
- **步骤3 — 多模态视觉模型识别：** 将图片直接送入多模态视觉模型进行识别。视觉模型相比传统OCR的核心优势：

| 识别能力 | 传统OCR | 多模态视觉模型 |
|---------|---------|---------------|
| 印刷文本 | ✓ 好 | ✓ 好 |
| 手写签名/批注 | ✗ 差 | ✓ 可识别 |
| 印章内容（弧形文字） | ✗ 极差 | ✓ 可提取 |
| 身份证照片+文字混合 | ✗ 只能识别文字区域 | ✓ 可同时读取照片和文字 |
| 表格结构（行列关系） | △ 需专门模块 | ✓ 原生理解表格 |
| 证件照片与文字的逻辑关联 | ✗ 无此能力 | ✓ 具备语义理解 |

调用视觉模型识别每张图片时，须提供其上下文锚点（从步骤1获得的"该图片所属章节/段落"），以便模型理解该图片的语义角色。**不在手册中硬编码具体模型名称**——后端可接入任意支持图像理解的多模态大模型。

- **步骤4 — 输出格式：** 视觉模型的识别结果输出为后续字段护照体系可用的结构化JSON，确保docx和PDF两种路径后续无差异化处理。

**PDF渲染+多模态视觉模型路径：**

> **架构原则：** PDF和docx两条路径在**图像理解层统一**——都使用多模态视觉模型作为最终的"阅读器"，不再使用传统OCR。差异只在**图片获取层**——docx从zip直接解包，PDF通过布局解析后提取。

**布局解析层：**

| 步骤 | 操作 | 说明 |
|------|------|------|
| 1 | 页面解析 | 布局检测模型将PDF每页拆分为结构化区域——正文段落、表格、图片、页眉页脚、公式。输出含每个区域的坐标和类型标签 |
| 2 | 原生文本提取 | 对"正文段落"区域，直接从PDF文本流提取（无OCR损失）。对"表格"区域，输出结构化表格 |
| 3 | 图片块提取 | 对标记为"图片"的区域，从PDF页面渲染中裁剪出对应区域的图像块，保留原始分辨率 |

**多模态视觉模型阅读层：**

以下三类关键证据**必须**送入多模态视觉模型，**禁止**使用传统OCR：

| 证据类型 | 处理方式 | 原因 |
|---------|---------|------|
| 公章/签名章/骑缝章 | 视觉模型读取印章中的弧形文字、签章样式，判定是否存在双签双章 | 传统OCR对弧形文字识别率趋近于零 |
| 身份证/社保卡/资质证书 | 视觉模型同时读取证件照片和文字信息，核验人证合一 | 传统OCR只能提取文字块，丢失照片比对 |
| 社保明细表/纳税凭证表/报价表 | 视觉模型理解表格的行列语义关系，输出结构化JSON | 传统OCR需额外的表格识别模块，行列错位率高 |

对于印刷正文，布局解析已提取的原生文本直接使用，无需送入视觉模型。

**备选路径（布局解析不可用时）：** 降级为PDF→300dpi全页渲染→多模态视觉模型逐页阅读。无论采用哪种降级路径，**图像理解层都统一使用多模态视觉模型，不回归传统OCR**。

#### 3.4.1 文本全文提取（文本层）

对各路径产出的文本进行汇总，生成统一的全文索引。将文本合并为统一的全文语料，按"章节标题→段落编号→文本内容"组织索引，供后续关键词搜索和字段定位使用。

#### 3.4.2 文档类型自动分类

投标人上传的资质证明文件通常是多个PDF文件或合并后的单个PDF。在提取字段之前，须先识别每份文件/每页的文档类型。

**分类策略（三级路由）：**

**第一级：文件名关键词匹配**

| 文件名包含关键词 | 判定为 |
|----------------|--------|
| `营业执照` / `统一社会信用代码` / `营业执照副本` | 营业执照 |
| `保密资格` / `二级保密` / `保密资质` / `武器装备科研生产` | 保密资质证书 |
| `社保` / `社会保险` / `缴纳明细` / `社保证明` | 社保缴纳凭证 |
| `纳税` / `完税` / `税收` / `税务` | 纳税证明 |
| `审计` / `财务报告` / `会计师事务所` / `资产负债表` | 审计报告 |
| `授权` / `委托书` / `法定代表人授权` | 授权委托书 |
| `保证金` / `投标保证金` / `保函` / `缴纳凭证` | 投标保证金凭证 |
| `业绩` / `合同` / `销售合同` | 业绩合同 |
| `进账` / `银行收款` / `银行回单` / `进账单` | 银行进账单 |
| `验收` / `验收报告` / `用户验收` | 用户验收单 |
| `承诺` / `声明` / `承诺函` / `声明书` | 承诺书/声明书 |
| `软著` / `软件著作权` / `计算机软件著作权` | 软件著作权证书 |
| `专利` / `发明专利` / `实用新型` | 专利证书 |
| `高新` / `高新技术企业` | 高新技术企业证书 |
| `ISO` / `GJB9001` / `质量管理体系` | 质量管理体系认证 |

**第二级：文本关键词匹配**

若文件名无法判定（如`附件1.pdf`、`扫描件_001.pdf`），对提取的全文执行关键词匹配：

| 文本中同时出现 | 判定为 |
|---------------|--------|
| `统一社会信用代码` + `法定代表人` + `注册资本` | 营业执照 |
| `武器装备科研生产单位` + `保密资格` + `有效期` | 保密资质证书 |
| `社会保险` + `缴费` + `参保单位` | 社保缴纳凭证 |
| `会计师事务所` + `审计报告` + `注册会计师` | 审计报告 |
| `致：` + `法定代表人授权书` + `授权代表` | 授权委托书 |

**第三级：人工标注兜底**

前两级均无法判定的文件，ORA在审查报告中列入"待人工确认的文件清单"，请求用户逐一标注文档类型后重新处理。

**输出：** 生成`document_index`，记录每份文件的类型、页码范围和分类置信度。

#### 3.4.3 字段护照体系（Document Field Passport）

为每种资质文档定义"字段护照"——一份声明了**字段名、提取方法、校验规则、容错策略**的规范。后续BCA和FCA的每项检查，直接引用护照中的字段名。

**护照模板（通用结构）：**

```json
{
  "doc_type": "社保缴纳凭证",
  "fields": [
    {
      "field_name": "参保单位名称",
      "extraction_method": "定位'参保单位'/'单位名称'/'缴费单位'→提取冒号后至行尾文本",
      "validation": "须与营业执照上的公司名称丝毫不差",
      "tolerance": "零容忍——逐字比对，含括号全角/半角",
      "fallback": "提取置信度<85%时标记'需人工复核'"
    }
  ]
}
```

**以下为7类核心文档的字段护照定义：**

##### A. 营业执照

| 字段名 | 提取方法 | 校验规则 |
|--------|---------|---------|

**社保月份提取专项说明：**

社保凭证的月份格式在不同城市/社保局可能不同，须兼容以下常见格式：
- `2025年01月 - 2025年01月`（单月，逐行列出）
- `202501`（6位数字，YYYYMM）
- `2025.01-2025.03`（时间段，代表连续3个月）
- 表格列名可能为："费款所属期""缴费所属年月""税款所属期""申报期"
- 在表格输出中逐行解析，合并去重后按时间排序，生成连续的月份数组（如`["2025-01", "2025-02", "2025-03", "2025-04"]`）

**印章/签名存在性检测专项说明（审计报告最重要的检查项）：**

因为"双签双章"是最高频的废标点之一，须采用专门策略：
1. **公章检测：** 报告正文末尾附近搜索红色圆形/椭圆形图像块，长轴直径须>100px（排除页码标记等小红点误检）
2. **个人印章检测：** 注册会计师姓名右侧搜索红色方形小图像块（通常60-120px），须恰好2个
3. **签名笔迹检测：** 注册会计师姓名旁搜索非印刷体的手写笔迹区域
4. **输出：** 生成审计报告印章验证记录，记录每个印章/签名的检测位置、置信度和判定结果

**格式兼容与废标风险矩阵：**

以下为各类证件的常见格式变体及提取失败时的fallback策略。关键原则：**字段设计聚焦于"是否导致废标"和"是否有效"。**

**A. 营业执照——关键字段格式兼容：**

| 字段 | 常见格式变体 | 提取策略 | 废标风险 |
|------|------------|---------|---------|
| 统一社会信用代码 | 18位连续字母数字 / 含空格分组（如`9133 0100 MA27 XX01 0X`） / OCR识别混入I/1、O/0、S/5 | 去空格后正则校验，对易混淆字符做二次确认（I→1, O→0只在8/9位校验位不通过时尝试） | 格式不通过标记为"待人工复核"，不直接否决 |
| 公司名称 | 全称（如"XX科技有限公司"）/ 简写缺"有限公司" / 含括号全角半角差异 | 先全称匹配，全称失败时去掉"有限公司""股份有限公司"后缀再匹配。括号统一转换为半角后比对 | **名称不一致直接否决**（零容忍） |
| 营业期限 | `至2028年12月31日` / `2038-12-31` / `长期` / 仅标注起始日无截止日 / `自成立之日起XX年` | 正则提取截止日期，标注"长期"的直接通过。仅标注起始日的，从成立日期+经营年限反推 | **过期直接否决** |
| 成立日期 | `2010年5月18日` / `2010-05-18` / `2010/5/18` / `2010.05.18` | 统一转换为YYYY-MM-DD，计算至投标截止日是否≥3年 | **不足3年直接否决** |
| 注册资本 | `500万元` / `500万元整` / `5000000.00元` / `500万` / `伍佰万元整`（大写） | 提取数值，统一换算为"万元"单位。大写金额需AI转换为阿拉伯数字 | 不满足招标最低要求标记为否决项 |

**B. 保密资质证书——关键字段格式兼容：**

|------|------------|---------|---------|
| 有效期起止 | `2022年03月01日至2027年03月01日` / `2022.03-2027.03` / `有效期：五年（2022.03.01-2027.03.01）` / 仅标注发证日期 | 正则提取日期段。仅标注发证日期的，参照资质有效期标准年限推算 | **过期或换证期无正式通过证明直接否决** |

#### 3.4.4 字段校验对撞引擎

完成所有文件的字段护照提取后，DPA生成一份统一的`extracted_fields`（所有文件的字段值全集）。后续BCA和FCA的所有检查逻辑，**不再直接操作PDF文件，而是基于此JSON文件执行校验对撞**。

**对撞引擎的5种校验模式：**

| 模式 | 逻辑 | 示例 |
|------|------|------|

| **值-阈值比对** | 数值字段是否满足最低/最高限制 | 业绩合同.累计金额 ≥ 500万元 |
| **值-日期比对** | 日期字段是否在有效期内 | 保密资质.有效期截止 > 开标日期 |
