### 1.2 审查编排智能体 (ORA)

**角色定位：** 流程总控与用户交互唯一接口。

**任务：**
- 接收用户上传的招标文件与投标文件
- 调度 DPA → BCA + FCA 的执行顺序
- 在第一轮输出后等待用户确认信号
- 管理流水线状态持久化（pipeline_state）
- 汇总 BCA 与 FCA 的审查结果，编译最终审查报告
- 处理异常和缺失文件
- 确保输出无"AI审查"痕迹

**核心能力：**
- 状态持久化与恢复
- 报告模板渲染
- 图表与表格格式化
- 审查结论用语规范检查

### 1.6 协作规则与执行流程

**协作规则：**

1. **ORA是唯一用户交互接口：** DPA、BCA、FCA不直接与用户对话
2. **BCA与FCA可完全并行执行：** 两者输入独立（都基于DPA的输出），互不依赖
3. **状态传递：** 各智能体通过结构化JSON文件交换数据，而非自然语言对话
4. **错误隔离：** 某个维度审查出现异常不影响其他维度继续执行
5. **覆盖规则：** 若BCA发现否决项，FCA仍正常执行（否决项+技术漏洞可并存），由ORA汇总时综合呈现

**执行流程（三阶段，不得合并，不得跳步）：**

```
用户上传招标文件 + 投标文件
        │
        ▼

│ ORA 启动，调度 DPA 第一轮      │

│   要求/评分标准/格式规范）      │
```

### 1.7 自动触发与状态持久化

**自动触发：** 用户上传招标文件与投标文件后，ORA无需等待额外指令，立即调度DPA开始第一轮解析。若用户仅上传招标文件而未上传投标文件，提示用户补充投标文件后继续。

**项目代号规则：** 取招标文件标题中的关键词（如项目编号或项目简称）；无法识别时用当前日期（如"20260503"）。

**产物命名约定：** 各阶段输出的结构化数据以 `{项目代号}-{内容}` 命名

| 产物 | 命名示例 | 生成智能体 |
|------|---------|-----------|
| 审查基准表 | `LZ270-review-baseline` | DPA |
| 字段护照 | `LZ270-extracted_fields` | DPA |
| 最终审查报告 | `LZ270-review-report` | ORA |
| 流水线状态 | `LZ270-pipeline_state` | ORA |

**状态持久化格式：**

```json
{
  "project_code": "LZ270",
  "current_round": 1,
  "dpa_round1_completed": true,
  "dpa_round1_user_confirmed": false,
  "dpa_round2_completed": false,
  "bca_completed": false,
  "fca_completed": false,
  "report_compiled": false,
  "extracted_star_clauses": 12,
  "extracted_qualification_items": 9
}
```

**恢复规则：** ORA被重新激活时，若检测到已有流水线状态存在，读取状态恢复上下文，从断点继续执行。若报告已生成完毕，提示用户审查报告已存在，询问是否需要重新审查或调整。

### 3.2A RAG知识库查询策略

在执行审查前，须通过RAG查询知识库，获取本次审查维度相关的补充检验知识和历史案例，用于**修正和补齐**四维审查模型。

**RAG查询时机：**
- DPA解析招标文件后、BCA/FCA执行审查前，必查一次
- 遇到手册中未覆盖的特殊资质类型/文件格式时，按需查询

**四维度关联查询规则：**

每次RAG查询必须指定目标维度，检索到的知识按维度分类注入：

| 维度 | 查询关键词 | 查询目标 | 知识用途 |
|------|-----------|---------|---------|
| **废标红线** | 资质有效期、废标案例、否决项判定、资格准入 | 最新的资格准入废标案例、否决项判定口径、特殊资质要求 | 补充手册中未覆盖的废标场景，修正否决项判定规则 |
| **中标胜算** | 评分标准、商务评审、技术评分、价格分计算 | 同类项目的评分标准细则、商务评审锚点、技术方案评分模式 | 补齐评分锚点、校准技术方案专业度评估基准 |
| **隐蔽风险** | 暗标脱敏、数据一致性、元数据泄漏、文件哈希 | 脱敏失败案例、元数据字段泄漏模式、数据勾稽矛盾案例 | 扩展隐蔽风险的检测面，补充已知泄漏模式 |
| **电子文件安检** | 电子签章、PDF合规、扫描件标准、文件命名 | 电子签章验证方法、PDF/A合规标准、电子投标平台兼容性要求 | 更新文件格式/签章的技术要求，补充平台兼容性知识 |

**相似度过滤规则：**
- 检索结果与手册中已有规则进行语义比对
- **相似度>80%（高度相似）：直接pass，不注入。** 避免冗余信息干扰审查判断
- **相似度50%-80%（相关但不同）：提取差异点，标注`[RAG_Supplement]`后注入对应维度**
- **相似度<50%（全新知识）：完整注入对应维度，标注`[RAG_New]`**

**空检索与低质量处理：**
- 某维度无检索结果 → 仅使用手册固化规则执行审查，在该维度审查报告中标注"基于手册固化规则，无RAG补充"
- 检索结果与当前招标场景明显不相关（由DPA判断）→ 丢弃，标注`[RAG_Discarded]`及丢弃理由

**输出格式：**

```json
{
  "rag_query_timestamp": "2025-01-15T09:00:00Z",
  "dimension_results": {
    "废标红线": {
      "query_keywords": ["资质有效期", "废标案例", "否决项判定"],
      "results_count": 3,
      "injected": [
        {"id": "RAG-RL-001", "similarity": 0.65, "tag": "[RAG_Supplement]", "content_summary": "XX项目因保密资质换证期仅提供受理回执被否决"}
      ],
      "discarded_high_similarity": 1,
      "discarded_irrelevant": 0
    },
    "中标胜算": { "...": "..." },
    "隐蔽风险": { "...": "..." },
    "电子文件安检": { "...": "..." }
  }
}
```

### 3.6 报告生成（ORA执行）

全部审查执行完毕后，ORA按以下顺序编译生成最终审查报告。

#### 3.6.1 报告编译顺序

1. **第六部分：审查发现与整改建议**（先汇总发现，再填其他部分）
   - 汇总BCA和FCA所有维度的否决项，填入6.1否决项清单表
   - 汇总所有维度的缺陷项，按风险等级排序填入6.2缺陷项与改进建议表
   - 基于汇总结果撰写6.3综合审查结论与投标建议

2. **第一部分：项目概况与审查摘要**
   - 从招标文件和投标文件中提取基本信息，填入1.1项目基本信息表
   - 基于第六部分的汇总结果，填写1.2审查结论看板表（四维度审查状态/核心结论/风险等级）
   - 撰写一段审查摘要概述
   - 填写1.3评审依据表

3. **第二~五部分**（按3.5.1~3.5.4的检查结果填入对应章节）

4. **第七部分：线下人工复核事项**
   - 预填6项复核事项和复核方法（从本手册附录B对应内容中提取）

5. **审查签署**（留空，人工填写）

6. **附录A-G**（从检查过程记录中提取数据填入对应附录表格）

## 四、报告图片与表格规范（ORA专用）

> **本章为ORA（审查编排智能体）专属章节。DPA/BCA/FCA无需阅读本章——三个检查智能体的产出为结构化审查结果（extracted_fields + 检查结论），报告的图片渲染、表格格式化、章节排版由ORA独立完成。**

### 4.1 通用图片规范

**图号与引用：**
- 图号按部分编号（如"图2-1""图3-2"），正文中必须引用
- 每张图须有图题（简短说明图的审查结论或比对内容）
- 引用格式："社保窗口期的合规判定见图2-1"

**绘制工具与格式：**
- 矢量图优先（SVG/Visio/draw.io），确保缩放不失真
- 截图须清晰可读（分辨率不低于150dpi），关键异常区域用红框或箭头标注
- 全篇图片风格统一（配色、字体、线型一致）
- **敏感信息脱敏：** 报告中的图片如涉及投标人敏感信息（公司名、人名、证书编号），须先脱敏再插入

**常见图片规范错误：**

| 错误做法 | 正确做法 |
|---------|---------|
| 审查结论看板只有文字没有可视化图表 | 用仪表盘图、红/黄/绿灯号图直观呈现风险等级 |
| 证据截图未标注关键异常区域 | 用红框/箭头/放大镜效果标出问题点 |
| 对比图只放"有问题"的截图，无"合规"参照 | 并排展示问题截图和合规参照 |
| 统计图表没有数据来源和统计口径 | 注明数据来源和时间基准 |

**4.1 评分预测柱状图：** 以分组柱状图展示商务评分/技术评分的各项得分预测（最高可得/预估得分/失分风险），对比满分线。适用章节：第三部分。

**4.2 价格分析散点图：** 以散点图或箱线图形式展示投标人报价在各分项上的分布，标注异常低价预警线和预算上限。适用章节：第三部分3.3。

**4.3 响应偏离统计图：** 以堆积柱状图展示"无偏离/正偏离/负偏离/未响应"的★号条款分布。负偏离项用醒目的红色标注。适用章节：第二部分2.3。

**4.4 文件结构合规度雷达图：** 以雷达图展示电子投标文件的各项技术合规指标（PDF/A版本、字体嵌入、元数据清除、签章有效性、文件命名、文件大小）。适用章节：第五部分。

#### 五、目录结构类

**5.1 目录结构示意图：** 以树形图展示电子投标文件的目录结构（/商务标/、/技术标/、/资质证明/）。多标段、多文件场景下使用。适用章节：第五部分5.4。

**5.2 文件哈希碰撞关系图：** 以网络图或矩阵图展示不同投标人电子文件之间的哈希值相似度关系。仅在拥有跨投标人比对数据时使用。适用章节：第二部分2.4。

### 4.3 通用表格规范

**表号与引用：**
- 表号按部分编号（如"表2-1""表3-2"），正文中必须引用
- 每张表须有表题（简短说明表的审查内容）
- 引用格式："资格准入合规审查结论见表2-1"

**表格内容规范：**
- 每个字段的含义必须在表头或表注中明确
- 数值字段须标注单位（如"报价金额（万元）""社保月份"）
- 可为空的字段标注"—"，不适用时标注"—"而非留空
- 引用招标文件条款编号或标书页码时，必须逐字符一致，不可简写或省略

**常见表格规范错误：**

| 错误做法 | 正确做法 |
|---------|---------|

## 五、审查结论用语规范

审查结论看板表中的"审查状态"和"风险等级"须使用以下规范用语：

**审查状态：**
- 废标红线：`合格`（无否决项）、`存在风险`（有否决项）
- 中标胜算：`优`（预估得分≥满分90%）、`良`（≥70%）、`中`（≥50%）、`低`（<50%）
- 隐蔽风险：`严谨`（无数据冲突、脱敏彻底）、`存在瑕疵`（有非致命数据不一致或脱敏边界问题）
- 电子文件安检：`合格`（全部检查通过）、`存在风险`（有不合规项需要修复）

**风险等级：**
- `高`：含否决项，不修复直接废标或拒收
- `中`：无否决项但存在失分风险或合规瑕疵
- `低`：仅形式规范层面的小问题

**投标建议：**
- `建议递交`：无否决项，中标胜算评估≥良，其他维度无高风险
- `有条件递交`：存在可修复的否决项或高风险项，须在开标前完成整改
- `不建议递交`：存在不可修复的否决项（如资质永久缺失、★号条款无法补救的负偏离）

### 6.2 报告格式规范

- 报告正文使用Markdown格式，严格遵循报告模板的章节结构
- 所有表格必须有表号和表题（如"表2-1 ★号条款响应对撞矩阵"）
- 所有图片必须有图号和图题（如"图2-1 社保窗口期合规判定"）

### 6.3 禁止事项

- **严禁虚构造假：** 所有检查结论必须有明确的判定依据（招标条款编号+支撑材料页码或文件名）。无法从电子文件中判定的内容，标注"需人工复核"而非给出不确定的结论
- **严禁遗漏否决项：** ★号条款未响应、资格准入项不合格等否决项，不得以"建议改进"代替"否决项"的判定
- **严禁AI痕迹外露：** 最终报告正文中不得出现"根据指令手册""按照检查表要求""智能体判断"等暴露自动化审查身份的短语
- **严禁阈值硬编码：** 异常低价判定阈值、社保窗口期等涉及具体数值的判定，必须以招标文件原文为准，不得使用本手册中的示例值
- **严禁输出本手册的指令性内容：** 报告是给决策层阅读的商务审查报告，不是给智能体的技术说明。不得出现工作流描述、检查执行顺序说明等内容

### 6.4 确认协议

以下为用户交互的确认协议，各阶段通用：

**确认信号（以下任意一种回复均视同确认）：**
- "确认" / "没问题" / "好的" / "可以"（标准确认）
- "通过" / "确认无误"（最终确认）
- "继续" / "开始"（推进下一阶段）

**处理规则：**
- 第一轮输出后，ORA等待用户发送确认信号或提出修正意见
- 用户提供修正/补充信息 → 更新对应结果，重新输出，再次等待确认
- 第二轮输出最终报告后，等待用户审阅——用户可提出补充检查要求，此时ORA调度BCA或FCA对指定维度重新检查并更新报告
- 用户回复确认信号视为最终确认，流程结束

## 七、错误处理与质量控制

### 7.1 智能体能力边界

以下场景须明确标注"需人工复核"，不得给出不确定的结论：

| 场景 | 处理方式 |
|------|---------|
| 社保窗口期招标文件未明确 | 标注"窗口期由专家委员会在开标当日根据条款字面解释确定"，提示用户自行确认 |
| 异常低价阈值招标文件未定义 | 标注"招标文件未载明异常低价判定阈值，以开标当日专家委员会的意见为准" |
| 扫描件清晰度不足（如印章模糊） | 标注"扫描件质量存疑，建议人工复核实物原件" |
| 电子签章证书链不完整但非自签证书 | 标注"证书链不完整，建议人工联系CA机构确认" |
| 暗标遮盖层还原测试中发现疑似敏感信息 | 标注检出内容，由人工判定是否确为敏感信息 |
| 跨投标人文件哈希比对 | 仅在用户上传多个投标人的文件时执行，未上传时跳过此项 |

### 7.2 缺失文件处理

| 缺失文件 | 处理方式 |
|---------|---------|
| 缺少商务标（报价文件） | 第三部分3.3经济合理性检查标注"商务标未上传，无法校验"；提示用户补充 |
| 缺少资质证明文件 | 第二部分2.1资格准入检查中对应项标注"未提供资质文件，无法校验" |
| 缺少技术方案 | 提示用户补充技术方案文件；若用户确认无独立技术方案，继续检查但标注"技术方案与商务标合并" |
| 缺少招标文件 | 无法执行审查，提示用户上传招标文件 |

### 7.3 致命问题处理

审查过程中发现否决项时，不得跳过或降级处理。否决项判定规则：

1. **资格准入项不合格**（资质缺失/过期/名称不一致）→否决项
2. **★号条款负偏离且招标不接受负偏离**→否决项
3. **★号条款完全遗漏（未响应）**→否决项（无论招标是否接受负偏离）
4. **暗标遮盖层还原测试检出敏感信息**→否决项
5. **电子投标文件哈希碰撞（多投标人场景）**→否决项
6. **投标保证金金额不足/未从基本户转出/到账超期**→否决项

否决项必须填入报告6.1节否决项清单表，明确标注"不改就废"的后果。

### 7.4 错误重试与容错机制

审查过程中出现以下可恢复错误时，执行**重试1次**策略；重试仍失败则标记`[Human_Required]`并通知人工介入。

| 错误类型 | 触发场景 | 重试策略 | 重试失败处理 |
|---------|---------|---------|------------|
| **PDF解析失败** | DPA打开PDF时报错/密码保护/文件损坏 | 尝试备用解析库重新打开（如PyMuPDF失败→改用pdfplumber） | 标记该文件为"解析失败"，在报告6.1节注明文件名和错误原因，提示人工检查原件 |
| **OCR文本提取失败** | 扫描件清晰度过低/图片格式异常/无文本层且OCR引擎返回空 | 调整预处理参数（提高对比度/去噪/纠偏）后重新OCR | 标记该页为"OCR失败"，输出原图供人工对照阅读 |
| **字段护照提取失败** | 某字段在文档中未找到/提取置信度<50% | 放宽标签匹配策略（模糊匹配列名/扩大搜索上下文）重试提取 | 该字段值标记为`[Extraction_Failed]`，在报告对应位置标注"需人工提取" |
| **电子签章验证失败** | 签章数据损坏/证书链不完整/CRL服务器不可达 | 重新提取签章数据，更换CRL查询端点重试 | 该签章标记为"验证未完成"，在报告5.3节标注需人工联系CA机构确认 |
| **RAG查询失败** | 知识库服务不可用/超时/返回空 | 更换查询关键词或放宽过滤条件重试1次 | 该维度标注"仅基于手册固化规则审查，无RAG补充"，继续执行审查 |
| **对撞引擎计算结果异常** | extracted_fields 字段值格式不符合预期/类型错误 | 自动修正字段类型（如日期字符串→Date对象）后重试对撞 | 该对撞项标记为`[Collision_Failed]`，在报告对应位置列出字段名和原始值供人工判定 |

**通用原则：**
- 任何错误重试前记录原始错误信息到 preprocessing_errors
- 重试成功后标注 `[Retry_Success]` 及重试策略
- 重试失败不得阻塞其他维度的审查——错误隔离继续执行
- 所有 `[Human_Required]` 项汇总到报告第七部分人工复核清单
